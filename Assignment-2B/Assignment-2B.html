Task 3: Performance Metrics

Using the values obtained from each confusion matrix, I will calculate accuracy, precision, recall, and F1 score for the 0.2, 0.5, and 0.8 thresholds. These metrics provide different ways of evaluating the model’s performance and allow me to compare how changing the probability threshold affects the results.

metrics <- tibble(
  threshold = c(0.2, 0.5, 0.8),
  TP = c(37, 36, 36),
  FP = c(6, 3, 2),
  TN = c(48, 51, 52),
  FN = c(2, 3, 3)
)

metrics
# A tibble: 3 × 5
  threshold    TP    FP    TN    FN
      <dbl> <dbl> <dbl> <dbl> <dbl>
1       0.2    37     6    48     2
2       0.5    36     3    51     3
3       0.8    36     2    52     3

Here tibble creates a small table and called it metrics, where each column stores one piece of information from the confusion matrices.

For accuracy we need to check how many did the model classify correctly. Accuracy=(TP+TN)/(TP+FP+TN+FN), so the model correctly classified about 91.4% of all observations at the 0.2 threshold.

For precision we need to check how many were actually female out of total predicted female. Precision= TP/(TP+FP), so of all the penguins the model called female at the 0.2 threshold, about 86.1% actually were female.

For Recall, we need to check how many did the model successfully identify as female of all the penguins that were actually female. Recall=TP/(TP+FN), so the model identified approximately 94.9% of the actual females.

–A useful distinction: Precision: When the model says female, how often is it right? Recall: Of all the actual females, how many did the model find?–

The F1 score combines precision and recall into one measurement. F1=2x(PrecisionxRecall/Precision+Recall).

metrics <- metrics %>%
  mutate(
    accuracy = (TP + TN) / (TP + FP + TN + FN),
    precision = TP / (TP + FP),
    recall = TP / (TP + FN),
    f1_score = 2 * (precision * recall) / (precision + recall)
  )

Here I calculated accuracy, precision, recall, and F1 score for each probability threshold using the values from the confusion matrices. Accuracy measures the proportion of all predictions that were correct. Precision measures how often the model was correct when it predicted female, while recall measures how many of the actual females the model successfully identified. The F1 score combines precision and recall into a single measure to evaluate the balance between the two.

metrics_table <- metrics %>%
  mutate(
    accuracy = round(accuracy * 100, 2),
    precision = round(precision * 100, 2),
    recall = round(recall * 100, 2),
    f1_score = round(f1_score * 100, 2)
  )

The results show that model performance changes as the probability threshold increases. At the 0.2 threshold, recall is highest at 94.87%, meaning this threshold identifies the greatest proportion of actual female penguins. However, its precision is lower at 86.05% because more male penguins are incorrectly classified as female.

At the 0.5 threshold, accuracy and precision improve while recall decreases slightly. At the 0.8 threshold, the model achieves the highest accuracy, precision, and F1 score of the three thresholds. Precision reaches 94.74%, indicating that when the model predicts female at this higher threshold, the prediction is more likely to be correct.

These results demonstrate the tradeoff created by changing the probability threshold. A lower threshold makes the model more willing to predict the positive class, which can improve recall but also increase false positives. A higher threshold makes the model more selective, which can improve precision but may increase the risk of missing positive cases.

Task 4: Threshold Use Cases

  • Describe at least one real-world scenario where:

    • A 0.2 threshold is preferable

    • A 0.8 threshold is preferable

0.2 Threshold

A lower threshold such as 0.2 could be useful in a healthcare setting when identifying patients who may be at risk for medication nonadherence and should receive additional review or outreach. With a lower threshold, the model would flag more patients as potentially at risk, including patients for whom the model has less certainty. In this situation, missing a patient who actually needs intervention may be more concerning than conducting an additional review or outreach for someone who does not. Therefore, a lower threshold may be preferred when identifying as many true positive cases as possible is important. This is reflected in the current analysis, where the 0.2 threshold produced the highest recall at 94.87%.

0.8 Threshold

A higher threshold such as 0.8 could be preferable when a positive prediction could result in a significant action and false positives need to be minimized. For example, if a healthcare model were used to identify potentially fraudulent claims for automatic denial, a higher threshold could require the model to have greater confidence before classifying a claim as potentially fraudulent. Incorrectly denying a legitimate claim could negatively affect both patients and providers. In this type of situation, higher precision may be more important because we want positive predictions to be highly reliable. In the current analysis, the 0.8 threshold produced the highest precision at 94.74%.
